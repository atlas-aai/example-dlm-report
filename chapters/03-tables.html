3  Tables

How to create tables in the report template.

This chapter focuses on tables. Tables are created with the gt package, and the gt_atlas() helper defined in _common.R applies the house formatting: decimal alignment, one decimal place for counts and percentages, three decimal places with no leading zero for values bounded by −1 and 1 (e.g., correlations and proportions), and an indent for rows within row groups. Captions are placed above tables, and table numbers are added automatically from the tbl- label.

3.1 Standard tables

3.1.1 Markdown tables

Small tables with fixed content can be written directly in markdown, as in Table 3.1. The caption and label follow the table on a line beginning with a colon.

3.1.2 Tables from data

Most tables are created from data with gt. Table 3.2 shows the distribution of performance levels by grade, using the default formatting from gt_atlas().

3.2 Text-heavy tables

Tables can also contain longer text. Column widths can be set with cols_width() so that text wraps within cells, as in Table 3.3. Table 3.3 also includes a footnote attached to a single cell, created with tab_footnote(). Use opt_footnote_marks(marks = "standard") to use symbols (*, †, ‡) rather than numbers, which could be confused with values in the table.

Text-heavy tables can also combine wrapped text with spanning headers and empty cells. Table 3.4 summarizes the sources of validity evidence for each claim, with empty cells shown as blanks using sub_missing(missing_text = "").

3.3 Grouped tables

3.3.1 Row groups

Rows can be organized into groups with the groupname_col argument of gt() (or with tab_row_group()). When a table has row groups, gt_atlas() indents the rows within each group, as shown in Table 3.5.

3.3.2 Spanning column headers

Related columns can be placed under a shared header with tab_spanner(). Table 3.6 uses spanners to group the count and percentage for each performance level, in addition to row groups. Wide tables like this one may need a smaller font (see Table 3.4) or a landscape page in the PDF.

To place a table on a landscape page, wrap the chunk in a .landscape div. In the PDF, the div starts a new landscape page and the text after it continues on a new portrait page. The website ignores the div.

::: {.landscape}

```{r}
#| label: tbl-spanners
#| tbl-cap: Science performance level distributions by demographic subgroup

subgroup_pl |>
  gt(groupname_col = "variable") |>
  ...
```

:::

Table 3.7 shows a common layout for survey results, with spanners for each response option, wrapped text in the first column, and a note defining the abbreviations used in the column headers.

3.4 Table notes and footnotes

Following APA style, general notes about a table are placed below the table, beginning with Note. These are created with tab_source_note(). Notes that apply to specific cells use tab_footnote(), which adds a mark to the cell and the matching footnote below the table.

3.4.1 Missing values and specific notes

Table 3.8 includes both kinds of notes. Missing values are shown with an em dash using sub_missing(), and footnotes explain why particular cells are empty.

3.4.2 Estimates with intervals

Estimates are often reported with an interval in parentheses, as in Table 3.9. Because these cells contain text rather than numbers, they are formatted before building the table (here with a small fmt_ci() helper defined in the setup chunk). Multiline column headers can be created with md() and <br>.

3.4.3 Signed values

Tables of differences or changes include negative values. gt formats these with a true minus sign (−) rather than a hyphen. In Table 3.10, extreme-value formatting is turned off with gt_atlas(fmt_extreme = FALSE) so that small changes are shown as numbers rather than as “<0.1”.

3.4.4 Proportions and many columns

Table 3.11 has many narrow columns under a single spanner. Proportions are formatted with three decimals and no leading zero, and the note gives the number of linkage levels summarized.

3.5 Long tables

By default, a table is kept on a single page in the PDF. Long tables can be allowed to break across pages by adding #| classes: breakable to the chunk options. The header row is repeated on each page, as shown in Table 3.12. On each page after the first, the caption is also repeated above the header, followed by “(continued)”.

3.6 Complex table captions

As with figures (Section 2.3), captions that require markdown formatting or inline code can be written by placing the table within a div. The tbl-scap attribute provides a shorter caption for the List of Tables at the beginning of the PDF document. The full caption is included after the R chunk that generates the table.

::: {#tbl-complex tbl-scap="Representation of demographic categories within retained student groups"}

```{r}
rep_tab |>
  gt(groupname_col = "variable") |>
  gt_atlas() |>
  ...
```

Representation of demographic categories within student group and linkage level combinations that met sample size for linkage level reliability (*N* = `r fmt_count(sum(rep_tab$comb_n[rep_tab$variable == 'Gender']))`)

:::
